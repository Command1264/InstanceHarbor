# InstanceHarbor 1.1.0

系統需求與安裝方式和 [1.0.0](windows-1.0.0.md) 相同。Windows x64 ZIP 請完整解壓後執行 InstanceHarbor.exe；Setup 為目前使用者安裝。Setup 尚未簽章。

## 新功能

- **系統匣改由 Manager 負責**：每個工作區一個圖示，顯示執行中的伺服器台數。關閉 GUI 後圖示仍在，伺服器照常執行。
  - 左鍵或「開啟」開啟 GUI；「結束」關閉 GUI 和 Manager，伺服器繼續執行。
  - 有伺服器尚未停止時，「結束」會先詢問（預設「否」）。開啟自動重啟的伺服器會另外說明：Manager 結束後，自動重啟要等 Manager 下次啟動才恢復。
  - 批次工作或核心更新進行中時，「結束」會拒絕並說明原因。
  - 視窗的關閉鈕改為結束 GUI，不再縮到系統匣。
- **Setup 自動關閉執行中的 InstanceHarbor**：更新或修復時，不再要求妳先自己關閉。
  - 還有伺服器沒停止時，Setup 停在等待頁並顯示台數，伺服器停止後自動繼續。Setup 不會替妳停止伺服器。
  - 靜默安裝（`/S`）遇到伺服器仍在執行時直接失敗（結束代碼 5），不改動任何檔案。
- **刪除伺服器資料改為移到資源回收筒**，並可從「已移除的實例」還原登記。
- **建立實例時加入管理資料夾**：實例不在任何管理資料夾內時，預設把上層資料夾加入管理資料夾，也可以改選實例資料夾本身、更上層的資料夾，或不加入。確認畫面會列出會一起登記的其他伺服器（名稱、核心、Port 與資料夾）。
- **測試管理員**：應用程式設定新增「測試管理員」分頁，最多 10 個身分。建立新實例時，可以透過 LuckPerms（全部權限或自訂權限節點，可指定群組）或 OP 授權。LuckPerms 只在設定頁明確下載，並以 SHA-256 核對。既有實例不會被改動。
- **實例名稱可以包含「.」**，例如 `paper-1.14.4`。名稱仍不能以「.」或「-」開頭，也不能以「.」結尾。
- **關於頁**顯示版本、建置 commit 與專案連結。

## 修正與改善

- 核心辨識：
  - 實例清單和核心維護顯示相同的核心版本。
  - 未登記的 Folia、Spigot 與舊版 Paper（例如 1.14.4）可以離線辨識，不再顯示「尚未核對」。
  - 核心名稱統一顯示為 Paper、Folia、Spigot、Velocity、Purpur，建置編號統一為「Build 134」。
- 實例狀態無法核對時，實例會留在清單上並顯示原因，可以複製不含路徑的診斷資料。
- 刪除伺服器時，只要其他實例的登記讀不到，就拒絕刪除，避免把其他實例的資料夾一起移到資源回收筒。伺服器資料夾已不存在時，仍可移除管理。
- 在管理資料夾內的實例「移除管理，清除管理設定」後，不會在下一輪掃描被重新登記。
- 建立實例時，改選管理資料夾選項的預覽失敗，選項會改回原本的並說明原因，背景會再讀取一次。
- 建立 Velocity 時，只開啟 OP（Velocity 沒有 OP）的話，預設不授權測試管理員，並說明原因。
- 系統匣「結束」在送出關閉訊息前，會核對 GUI 的程序身分，不會誤關其他程式。
- 診斷紀錄寫滿 2 MiB 後換到下一個檔案，整個資料夾保持在 16 MiB 以內。週期性的背景查詢只在結果改變時寫入。
- 主視窗與後台視窗會配合螢幕可用範圍調整大小。
- 對話框的焦點框不再被裁切。
- GUI 冷啟動時，第一份清單在 WebView2 建立期間預先讀取，畫面較快出現。
- GUI 視窗關閉後若仍未結束，10 秒後會自行結束，避免系統匣的 Manager 被重新啟動。

## 從 1.0.x 升級

1. 正常停止所有伺服器。
2. 執行 1.1.0 Setup。Setup 會請 1.0.x 的 Manager 結束。
3. Setup 等待頁出現時，從系統匣結束 1.0.x 的 InstanceHarbor GUI。1.0.x 的 GUI 不會自己結束，按視窗關閉鈕只會縮到系統匣。
4. GUI 結束後 Setup 自動繼續安裝。

## 回退到 1.0.x

- **建立或匯入名稱含「.」的實例後，請不要回退。** 1.0.x 讀到任何一個這樣的登記，整個實例清單都會讀取失敗（`InvalidInstanceName`）。
- 回退前請備份工作區，並正常停止伺服器、結束 GUI 與 Manager。

已知問題：GUI 結束時，目前要等上述 10 秒保護機制才會關閉，所以 Setup 更新時會多等約 10 秒（[#92](https://github.com/Command1264/InstanceHarbor/issues/92)）。

此公開版本使用合成路由資料。預設不替任何身分授予權限；請由使用者自行管理伺服器權限。
